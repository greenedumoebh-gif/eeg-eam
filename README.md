# نظام الخدمات المساندة المطور

**منصة ERP/EAM لإدارة دورة حياة الأصول — من المناقصة إلى الصرف** مجموعة الهندسة الإلكترونية · وزارة
التربية والتعليم · مملكة البحرين

مبني على **Deno + TypeScript**، بلا أي تبعية خارجية، جاهز للنشر على **Deno Deploy** أو داخل مركز
بيانات الوزارة.

---

## التشغيل خلال دقيقة

```bash
git clone <عنوان-المستودع>
cd eeg-eam
deno task start
```

افتح <http://localhost:8000> — النظام يبذر نفسه تلقائياً عند أول تشغيل ببيانات واقعية: ٨ أنواع أصول،
٥ مواقع، موردَين، عقدَين ساريين، ٥ أصول، وبندَي ميزانية.

### حسابات العرض

الأسماء مسمّيات أدوار لا أسماء أشخاص، والبريد على نطاق `demo.eeg` غير الحقيقي — لتبقى بيانات العرض
افتراضية بالكامل.

### البيانات الجاهزة عند أول تشغيل

٨ أنواع أصول · ٥ مواقع · موردَان · عقدان ساريان · ٥ أصول · بندا ميزانية، إضافةً إلى حركة تشغيلية
تمهيدية حتى لا تكون لوحة المؤشرات فارغة:

| الحالة                             | ما تُظهره                           |
| ---------------------------------- | ---------------------------------- |
| بلاغ مفتوح على آلة تصوير           | نقطة بداية لتجربة السلسلة من أولها |
| أمر عمل منجز على طابعة             | جاهز ليُفوتره المحاسب               |
| فاتورة مرّت المسار كاملاً وصُرفت      | تُظهر أثر الصرف على الميزانية       |
| بلاغ على كاميرا (عقد بدفعات دورية) | يوضّح أنه لا يُفوتَر منفرداً           |

## جرّب السلسلة كاملة في ٧ خطوات

هذا أفضل عرض لقدرات النظام. بعد الدخول:

1. **`engineer@demo.eeg`** → الأصول → افتح `COP-000001` → املأ «فتح بلاغ على هذا الأصل». لاحظ: النظام ربط
   البلاغ تلقائياً بالعقد الساري وحدد المورد وحسب موعد الاستجابة.
2. في صفحة البلاغ → **فتح أمر عمل**. الأصل ينتقل تلقائياً إلى «تحت الصيانة».
3. املأ تقرير الإنجاز والمبلغ المستحق (مثلاً `120`) → **اعتماد الإنجاز الفني**.
4. **إغلاق البلاغ**. الأصل يعود «في الخدمة» تلقائياً.
5. **`accountant@demo.eeg`** → الفواتير → اختر أمر العمل والمورد → **إنشاء مسودة فاتورة**. المبلغ
   محسوب من أمر العمل، والضريبة ١٠٪ مضافة، وبند الميزانية موروث من العقد. افتح الفاتورة → لاحظ
   **المطابقة الثلاثية** بفحوصها الأربعة → **تقديم للاعتماد**.
6. **`reviewer@demo.eeg`** → اعتماد. ثم **`approver@demo.eeg`** → اعتماد. عند الاعتماد النهائي يُحجز
   المبلغ على بند الميزانية (شاهده في تبويبة الميزانية).
7. **`payer@demo.eeg`** → **تنفيذ الصرف**. الحجز يتحول إلى صرف فعلي.

جرّب أيضاً: حاول أن يعتمد `acc` الخطوة التالية بنفسه — النظام يرفض بقاعدة **فصل المهام**.

## النشر على Deno Deploy

### الطريقة أ — من مستودع GitHub

1. ارفع المستودع **كاملاً** إلى GitHub، وتأكد أن مجلد `src/data` ظاهر في قائمة الملفات هناك.
2. من <https://dash.deno.com> ← **New Project** ← اربط المستودع.
3. نقطة الدخول: `src/main.ts`
4. أضف متغيرات البيئة (الجدول أدناه).

> ⚠️ **تحذير مهم:** النمط `data/` في `.gitignore` يطابق أي مجلد بهذا الاسم على أي مستوى، فيبتلع
> `src/data/` ويفشل البناء برسالة `Module not found`. لهذا النمط هنا `/data/` بشرطة مائلة في
> البداية. لا تعُد إلى `data/`.

### الطريقة ب — ملف واحد، بلا مستودع

```bash
deno task bundle      # ينتج dist/main.js
```

ملف واحد يحتوي النظام كاملاً بلا أي استيراد نسبي. الصقه في **Deno Playground** واضغط Save، أو ارفعه
وحده واجعله نقطة الدخول. لا شيء فيه يمكن أن ينقص.

نسخة مبنية جاهزة موجودة في `dist/main.js` داخل هذه الحزمة.

### متغيرات النشر

```
SESSION_SECRET=<نص عشوائي طويل — openssl rand -base64 48>
ALLOW_SEED_ENDPOINT=false
DEMO_MODE=true
```

Deno Deploy يوفّر Deno KV تلقائياً — لا إعداد قاعدة بيانات مطلوب.

### التحقق بعد النشر

```
https://<عنوانك>/healthz   →   {"ok":true,"driver":"kv"}
```

ثم سجّل الدخول بـ `engineer@demo.eeg` / `Demo@12345`.

> 📍 **قبل استخدام بيانات حقيقية اقرأ [`docs/DATA-RESIDENCY.md`](docs/DATA-RESIDENCY.md).** Deno
> Deploy ليس لها إقليم في البحرين. الوثيقة تشرح الخيارات وأيها يبقي البيانات داخل المملكة.

### قائمة تحقق قبل العرض على الجهات العليا

- [ ] `SESSION_SECRET` قيمة عشوائية جديدة (ليست الافتراضية)
- [ ] `ALLOW_SEED_ENDPOINT=false`
- [ ] `DEMO_MODE=true` — الشريط ظاهر في كل صفحة
- [ ] تغيير كلمات مرور الحسابات التجريبية قبل مشاركة الرابط
- [ ] لا تُدخِل أي بيانات فعلية للوزارة

## الانتقال إلى PostgreSQL (الإنتاج داخل البحرين)

```bash
DB_DRIVER=postgres
DATABASE_URL=postgres://user:pass@host.me-south-1.rds.amazonaws.com:5432/eeg?sslmode=require
```

فقط. النظام ينشئ المخطط تلقائياً من `src/data/schema.sql` عند أول تشغيل. لا سطر واحد من الكود يتغير —
كل الوصول للبيانات يمر من واجهة `Repo` واحدة.

## ما يميّز هذا النظام

**المطابقة الثلاثية مفروضة برمجياً.** لا تُقدَّم فاتورة للاعتماد قبل التحقق من: العقد ساري ولنفس المورد،
أوامر العمل منجزة بتقارير مكتملة، المبلغ مطابق للمحسوب، والسيولة متوفرة.

**فصل المهام لا يُتجاوز.** من صنع لا يراجع، ومن اعتمد لا يصرف — مفروض في المحرك نفسه، لا في التعليمات.

**المبالغ محسوبة لا مُدخَلة.** الفاتورة تُبنى من أوامر العمل، فلا مجال لخطأ إدخال ولا لتلاعب.

**لا فوترة مزدوجة.** أمر العمل يُوسَم بمرجع فاتورته لحظة إنشائها.

**أنواع أصول جديدة بلا كود.** الحقول الديناميكية تعني أن إضافة نوع بخصائصه سطر بيانات لا نشرة برمجية.

**البيانات حيث تقرر الوزارة.** طبقة مستودع مجرّدة تنقل النظام من Deno KV إلى PostgreSQL داخل البحرين
بمتغيّر بيئة.
